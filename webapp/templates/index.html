Static analysis for quantum programs

See how a quantum program actually fits together.

This project is designed to help visualize how quantum programs work, and to assist in debugging their code. Using code taken from a file or text input, it creates a fully interactive map that shows the functionality of the quantum code.

The map details the individual steps of a quantum circuit and maps out the connections between each step, sorting out entanglements and clarifying the relationship between qubits.

Classical programming is deterministic

The normal assumption of programming is that given a chosen input, a specific set of instructions will be executed to produce a certain outcome. This is what is known as classical programming, whose foundation is built upon bits, pieces of data that store either 0 or 1.

Although a classical program may have conditional branches and produce different results for different inputs, each individual execution follows a defined sequence of operations. One can be certain that given x, y will occur.

Quantum programming is not

Quantum programming runs against this type of deterministic programming by working with the probabilistic behavior of quantum systems. Instead of representing information exclusively as definite 0 or 1 values in bits, quantum programs operate on qubits.

These fundamental units of quantum information exist in a superposition, where a qubit can simultaneously be 0 and 1. Rather than representing several classical values as separate pieces of data, a quantum state can encode a combination of possible outcomes that is manipulated by quantum operations.

You read probabilities, not answers

Since a quantum program can produce every possible answer to a calculation, the output cannot simply be the list of solutions to a problem. Instead, quantum operations modify the probabilities associated with possible outcomes. Quantum algorithms are designed so that useful outcomes can be amplified while undesirable outcomes are reduced or cancelled through the behavior of quantum states.

When a qubit is measured, its quantum state produces a classical result. Repeated executions of a quantum program can therefore be used to observe the distribution of possible results and estimate their probabilities.

Programs are circuits, and circuits entangle

Quantum programs are commonly represented as quantum circuits, which consist of a sequence of quantum instructions, or gates, that operate on one or more qubits. Measurements convert quantum information into classical information, and classical information can subsequently influence other operations.

These circuits can become entangled. Entanglement occurs when the states of multiple qubits become related in a way that cannot be described by considering each qubit independently. What happens to one qubit in an entangled group is therefore vital to understanding the others.

The map: a Quantum Program Dependence Graph

The visualization used in this project is known as a Quantum Program Dependence Graph, or QPDG. A regular dependence graph represents relationships between instructions in a classical program; a QPDG extends this to represent quantum programs.

In it, each quantum instruction becomes a node, and edges between nodes represent dependencies between operations. Measurements can also create dependencies, when their classical results are used to determine later operations.

Slicing: the part that matters

Representing the ways each qubit affects the others, especially in entanglement, is made easier via program slicing. Program slicing identifies the portions of a program that are relevant to a particular instruction or result, a method used in both classical and quantum programming.

Backward slice

Starts with an instruction and traces back to the earliest instruction to influence it.

Forward slice

Does the opposite, working from a starting instruction to the last portion affected by it.

Why visualize it at all

Quantum programs can become difficult to understand as the number of qubits and operations increases. A circuit may contain many gates that interact indirectly through shared qubits, measurements, classical conditions, and entanglement. Reading the source code alone does not necessarily make these relationships obvious.

Visualization can simplify the process of viewing the various processes at play, which makes it easier to debug, to optimize, and to understand quantum programming generally.

What you can do with it

Slice from a gate

Pick any instruction and follow its dependencies backward to everything that feeds it, or forward to everything it can still affect.

Filter by dependency

Follow only data dependencies on qubits, only measurement dependencies, or any combination — each kind is a separate rule in the graph.

Read the entanglement

See which qubits have been pulled into the same group, how deep the nesting goes, and where uncomputation undid it again.

Catch mistakes early

Static checks run before your file is executed: out-of-range qubits, a circuit with no measurement, classical bits written twice, removed Qiskit APIs.
